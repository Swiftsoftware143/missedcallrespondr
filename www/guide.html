Overview

MissedCall Respondr is a call-response and follow-up automation platform. It captures incoming call data, lets you define custom response rules, sends automated text/callback replies, tracks follow-ups, and manages your contacts — all from one dashboard.

Built for businesses that never want to miss a lead or client callback, MissedCall Respondr helps you close the loop on every inbound call.

Getting Started

Accessing the App

Open your browser and navigate to:

https://app.missedcallrespondr.com/

Login Credentials

Sign in with the email address and password issued to your account. The password is generated by the system and emailed to you when the account is created, so keep that message.

Logging In

  1. Visit the app URL above.
  2. Enter your email address and password.
  3. Click Sign In.
  4. You land on the Overview screen.
🔒 Password Reset Forgot your password? Click "Forgot Password?" on the login screen to receive a reset link via email.

API Access

All platform resources are also available via the REST API at:

https://app.missedcallrespondr.com/api/v1/

The tenant console is a client of this API. There is no API-key capability on a tenant account: the console has no API-keys screen and the API-key routes were removed, because a key minted there was accepted by no endpoint. Every route the console uses takes your signed-in session instead. Machine access to your own data is not a self-serve feature — ask the platform operator.

Dashboard — the Overview screen

The first screen is the Overview. It summarises what is set up on your account — it is not a traffic report and it has no date-range picker.

Summary Cards

Four counters, each the total number of rows on the matching screen:

Card What it counts
Response RulesResponse rules defined for this account.
TemplatesSaved message templates.
ContactsContacts in the directory.
Auto-ResponsesAutomated responses the platform has sent.

Credits & Phone Numbers

Under the counters are two cards: Credits, which shows the calling credits left on the account, and Phone Numbers, which points at the Phone Numbers screen.

There is no chart on this screen The Overview shows counters and credits only. Call-volume charts, a missed-vs-answered breakdown and a recent-activity feed are not part of the console; the per-call record is on the Call Log.

Call Log

The Calls screen (the Call Log in the sidebar) lists this account's inbound calls, newest first. It is a plain table with a Refresh button and an Export CSV button.

Table Columns

Column Description
CallerThe caller's name when the number matches a contact, otherwise the number.
CalledThe number the caller dialed (yours).
WhenWhen the call came in.
DispositionWhat happened to the call (missed, answered, …).
ActionRespond — offered on a missed call. It queues a call-back follow-up (it appears in Follow-ups).

The table shows the most recent 100 calls; Refresh reloads it from GET /api/v1/calls.

Export CSV downloads the call log as call-log.csv, one row per call, with the columns ID, Caller, Called, When, Duration Seconds, Disposition. Caller follows the table's own rule — the name when one is known, the number otherwise. The file comes from GET /api/v1/call-logs/export, which reads the same table this screen lists, so the download cannot disagree with the rows above it; unlike the table it is not capped at 100 rows. CSV is the only format.

What the Calls screen does not have There is no search box, no status filter and no date range, and no row-click detail panel — so there is no call timeline, no note field and no per-call view. The row is the whole record the console shows; what the rules did is visible on Messages and Follow-ups.

Phone Numbers

Phone Numbers lists the numbers this account holds, read from GET /api/v1/telnyx/numbers. + Add Number adds one, and the Release button on a row removes it from the account.

ColumnDescription
NumberThe number itself.
Statusactive while the account holds the number.
AddedWhen the number was added to the account.

Adding a Number

+ Add Number takes the number with its country code (for example +15551234567) and an optional label. How the number is acquired depends on the account: when the platform holds a Telnyx credential the number is bought on the platform's Telnyx account, and when the account has connected its own Telnyx key under Integrations (Pro and Enterprise plans) the number must already be yours on Telnyx and is registered here. How many an account may hold is the plan's own limit (Free 1, Pro Monthly 5); at the cap, or when the platform has no Telnyx credential saved, the server's own message is shown and nothing is added.

Releasing a Number

Release (confirmation required) removes the number from the account and frees the plan slot, so it leaves this list and can be added back later. The platform operator can also provision and release numbers for an account.

Response Rules

Response Rules are the heart of MissedCall Respondr. They define when and how the system automatically replies to an incoming call.

Creating a Rule

  1. Navigate to Response Rules in the sidebar.
  2. Click + Add Rule.
  3. Fill in the rule fields (see table below).
  4. Click Add (or Save when editing). From that moment the rule is evaluated on every inbound call.
Field Description
NameA label to identify the rule (e.g. "After-Hours Auto SMS").
TriggerWhen the rule fires: All missed calls, Specific numbers, Time of day, or Day of week. One trigger per rule.
Trigger detailsWhatever the trigger needs — the caller numbers (Specific numbers, one per line), the From/To window (Time of day), or the days (Day of week).
ActionSMS (text the caller back) or Callback (queue a return call for you in Follow-ups, due in an hour).
MessageFor an SMS rule, the text to send. It goes out exactly as typed — no placeholders are substituted.
PriorityRules are evaluated in priority order (lowest number first; the default is 100).
EnabledToggle the rule on/off without deleting it.

Rule Evaluation Order

Every inbound call walks your enabled rules in priority order (lowest number first, oldest first where two rules share a priority). The first rule whose trigger matches fires, its action runs, and the rest are skipped for that call. If no rule matches, the call is logged and nothing is sent.

What an SMS Needs

A text leaves through Telnyx, from the number the caller dialed. Until an administrator has saved the Telnyx API key and messaging profile under Admin → Telnyx Config, no text can go out — a rule still fires and is logged, but the Messages screen stays empty because nothing was attempted. Queued, sent, delivered and failed on the Messages screen are always the provider's own answer.

Managing Rules

  • Edit — click Edit on any rule row.
  • Delete — click Delete (confirmation required).
  • Re-order — change the Priority number; the list is shown in evaluation order, so what you see is the order the calls are checked in.
📌 Example Rule

Name: "Weekend Auto-Reply"
Trigger: Day of week — Sat, Sun
Action: SMS — "Thanks for calling. We're closed for the weekend and will call you back on Monday."
Priority: 10

Follow-ups

Follow-ups is the call-back queue. Rows arrive on their own: the Respond button on a missed call schedules a call-back and a Callback response rule queues one automatically. You can also schedule one by hand with + New Follow-up, close it, or delete it.

What the Screen Shows

ColumnDescription
CallThe call the follow-up was raised for — the caller and when it came in. Every follow-up is attached to one of your calls.
ScheduledWhen the call-back is due.
StatusThe task's state as the server stores it — pending while the call-back is still due, completed once it is closed.

The list is read from GET /api/v1/follow-ups.

Managing Follow-ups

  • + New Follow-up — pick one of your calls, a type (the app's own value is call_back), the due date and time, and optional notes (POST /api/v1/follow-ups). A follow-up is always attached to a call (call_id is a required foreign key), so the button stays off until the account has at least one call.
  • Mark done — closes a follow-up (PUT /api/v1/follow-ups/:id with status completed plus the completion time).
  • Delete — removes it (confirmation required).

There is no status filter, no search box and no Assigned To field: the list is every follow-up on the account.

Contacts

Contacts is the directory of the people this account talks to. Each row shows a name, phone and email.

Searching

The search box searches on the server as you type (GET /api/v1/contacts/search?q=) across name, phone and email. Clearing it returns the full list, and Refresh reloads it.

Custom Fields

Custom fields store extra per-contact data. The button shows how many fields are defined and opens a panel where you can:

  • Add a field — a name, a type (text, number, date or boolean) and an order.
  • Delete a field — its per-contact values go with it.
  • Fill in values — once at least one field exists, each row gets a Fields button that opens that contact's values and saves them with PUT /api/v1/contacts/:id/fields/:field_id.

Adding and Editing Contacts

  • + New Contact — name and phone are required; email, company, tags (comma separated) and notes are optional (POST /api/v1/contacts).
  • Edit — reopens the row in the same form and saves with PUT /api/v1/contacts/:id. Emptying an optional box clears that field.
  • Delete — removes the contact and its custom-field values (DELETE /api/v1/contacts/:id, confirmation required).

A duplicate email inside the same account is refused by the server, which shows its own message. There is still no contact detail page — clicking a row does nothing, and the row's Fields button opens the custom-field values. Contacts are not created automatically from inbound calls; a new caller reaches your CRM through the CoreSwift integration (Integrations), which captures every missed call as a lead.

Tickets

Tickets is the support-ticket list, read from GET /api/v1/tickets. Each row shows a subject, a status and a priority.

  • + New Ticket — creates a ticket with a subject, a status (Open, In Progress, Resolved, Closed) and a priority (Low, Medium, High, Urgent).
  • Edit — reopens a ticket to change its subject, status or priority.

Message Templates

Message Templates are saved message texts you keep for reuse. A template is a library entry and nothing more: nothing sends one automatically, and a response rule carries its own Message text. Copy the wording from a template into the rule's Message field when you want to reuse it.

No Variable Substitution

Whatever you type is what the caller receives. {{name}}, {{company}} and the like are not replaced — a rule that sends Hi {{name}} texts the caller the literal words. Write the message you want them to read.

Creating a Template

  1. Go to Message Templates → + Add Template.
  2. Enter a name (e.g. "After-Hours SMS").
  3. Write the message body.
  4. Click Add. It is kept in this list for you to copy from.
📌 Example

Sorry we missed your call! We're on it and will ring you back shortly.

Editing & Deleting

Templates can be edited or deleted from the same list. Deleting a template does not change any rule — rules hold their own message text and never reference a template.

Messages

The Messages tab is the outbound text log and the place you send a text by hand. + Send Message opens a form pre-filled with a number this account holds as the From number; enter the recipient and the text and press Send. The message is transmitted from your own Telnyx number, and the row records what the provider reports — nothing is marked sent or delivered that the provider did not confirm.

What each status means

Status What happened
queuedTelnyx accepted the message. It has not been handed to the recipient's carrier yet.
sentThe carrier took the message. The Sent column shows when Telnyx reported this.
deliveredThe recipient's network confirmed delivery. The Delivered column shows when Telnyx reported this.
failedThe provider refused the message or the carrier reported a failure. The reason Telnyx gave is shown in a dialog when you send; the attempt stays in the log as failed.
loggedA message recorded as received (inbound). Nothing is transmitted for these.
ℹ️ Sending needs a connected number

The From number must be a number this account holds — see the Phone Numbers tab in the app. If the platform has no Telnyx credential saved yet, sending answers "Text delivery is not configured" and nothing is recorded: an operator has to save the Telnyx API key and the messaging profile of a messaging-enabled number first.

Integrations

Integrations is the provider catalogue for this account. Each card shows a status badge — Connected or Not connected — and the controls that apply to it. The catalogue is read live from GET /api/v1/available-providers, so a provider added on the platform appears here without a console release.

Connecting a Provider

  1. Paste the provider's API key into the field on its card.
  2. Click Connect. A provider that can use another endpoint also shows an optional Base URL field.
  3. Click Test connection to run the live probe. CoreSwift is probed against the hub and reports whether the key was accepted; for the other providers the platform answers that no live test is available yet.
  4. Click Disconnect to remove the stored key.

Once CoreSwift is connected its card also shows the hub URL and a Push a lead to CoreSwift now form, which runs the same push the automatic capture path uses for a lead you captured by hand.

CoreSwift is the integration the call path uses Every inbound call is captured as a lead in CoreSwift. The other providers in the catalogue store a key for the platform's own use; they are not switches on the call flow.

Profile & Account

The Profile screen (the last item in the sidebar) holds your own account details. There is no separate "Settings" page.

Your Details

  • Email — shown read-only; it identifies the account.
  • Name — editable, saved with Save profile (PUT /api/v1/auth/profile).

Change Password

Enter your current password and a new one (at least 8 characters) and click Update password (PUT /api/v1/auth/password).

There is no Settings page Phone, timezone, company profile, logo, notification preferences and business hours are not part of the console, and the account-settings and API-key routes were removed from the API — nothing read a stored tenant setting, so those screens were deliberately not built. No response rule references business hours either: a rule's trigger is All missed calls, Specific numbers, Time of day or Day of week (see Response Rules).

Frequently Asked Questions

How does MissedCall Respondr receive call data?

Your VoIP provider (Telnyx) sends webhooks to MissedCall Respondr's API. Configure the webhook URL from your provider's dashboard to point to https://app.missedcallrespondr.com/api/v1/telnyx/webhook. That one public URL carries both the call events (which raise the Call Log entry and run your Response Rules) and the message delivery events (which set a text's Sent/Delivered times).

Can I have multiple response rules active at the same time?

Yes. Rules are evaluated by priority. Only the first matching rule fires per call. You can keep as many rules as your plan allows, each with its own trigger and priority.

What happens if no rule matches a call?

The call is still logged on the Calls screen, but no automated response is sent. You can handle it from that row with Respond, which queues a call-back follow-up.

Are message templates required for SMS responses?

No. Type your message straight into the rule's Message field. Message Templates are a separate library you keep for reuse — a rule never references one, so copy the wording in if you want to use it.

How do I export my call data?

Open the Calls screen and click Export CSV. The file call-log.csv holds every call on the account — not just the 100 the table renders — with the columns ID, Caller, Called, When, Duration Seconds, Disposition. It is the same data the table lists, and CSV is the only format.

What variable syntax does the app support?

None for the text a rule sends. Messages and templates are sent exactly as typed — {{name}}, {{company}} and the other double-curly-brace forms are not replaced, so write the finished sentence you want the caller to read. (The app's own account emails — welcome, password reset, purchase — do fill in their own fields; that does not apply to the text a Response Rule sends.)

How do I reset my password?

On the login page, click "Forgot Password?" and enter your email address. You'll receive a password reset link. You can also change your password under Profile → Change password while logged in.

Is there a mobile app?

The MissedCall Respondr web app is fully responsive and works on mobile browsers. There is no native iOS/Android app at this time.

How do I contact support?

Email support at support@missedcallrespondr.com.
